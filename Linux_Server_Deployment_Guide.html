เตรียมความพร้อม Linux Server & ติดตั้ง Docker

ติดตั้ง Docker Engine, Docker Compose Plugin และเปิดพอร์ต Firewall ที่จำเป็น

เชื่อมต่อไปยัง Linux Server ของคุณผ่าน SSH แล้วรันคำสั่งติดตั้ง Docker Engine อย่างเป็นทางการ:

bash (SSH Terminal) 
# 1. อัปเดตแพ็กเกจระบบ
sudo apt-get update && sudo apt-get upgrade -y

# 2. ติดตั้งเครื่องมือพื้นฐาน
sudo apt-get install -y ca-certificates curl gnupg lsb-release git

# 3. ติดตั้ง Docker และ Docker Compose Plugin
curl -fsSL https://get.docker.com -o get-docker.sh
sudo sh get-docker.sh

# 4. อนุญาตให้ User รัน Docker โดยไม่ต้องพิมพ์ sudo (แทนที่ $USER ด้วย user ของคุณ)
sudo usermod -aG docker $USER
newgrp docker

# 5. ทดสอบว่า Docker พร้อมใช้งาน
docker compose version
🛡️
การตั้งค่า Firewall: เปิดพอร์ตที่จำเป็นตามระบบปฏิบัติการของ Server (รันในฐานะ root ไม่ต้องพิมพ์ sudo):

แบบที่ A: สำหรับ CentOS / AlmaLinux / Rocky Linux / RHEL (ใช้ firewall-cmd)

firewall-cmd --permanent --add-port=5173/tcp  # Web Frontend UI
firewall-cmd --permanent --add-port=8125/tcp  # Backend API (Direct / Healthcheck)
firewall-cmd --permanent --add-port=8123/tcp  # QA Agent DB (pgvector)
firewall-cmd --permanent --add-port=8124/tcp  # Spectra Auth DB
firewall-cmd --permanent --add-port=8000/tcp  # MCP SSE Endpoint
firewall-cmd --reload
firewall-cmd --list-ports                     # ตรวจสอบพอร์ตที่เปิด

แบบที่ B: สำหรับ Ubuntu / Debian (ใช้ UFW)

# หากเครื่องยังไม่มี ufw ให้ติดตั้งก่อน: apt install -y ufw
ufw allow 22/tcp    # SSH (อย่าลืมเปิดก่อน enable)
ufw allow 5173/tcp  # Web Frontend UI
ufw allow 8125/tcp  # Backend API (Direct / Healthcheck)
ufw allow 8123/tcp  # QA Agent DB (pgvector)
ufw allow 8124/tcp  # Spectra Auth DB
ufw allow 8000/tcp  # MCP SSE Endpoint
ufw enable
ufw status

Clone Repository & ตั้งค่า Environment (.env)

ดึงซอร์สโค้ดจาก Git และสร้างไฟล์ตั้งค่าความปลอดภัยของระบบ

bash 
# 1. Clone โปรเจกต์ลงมายัง Server
git clone https://github.com/AkradTTT08/OCR-Document.git
cd OCR-Document

# 2. สร้างไฟล์ .env จากแม่แบบ .env.example
cp .env.example .env

# 3. เปิดไฟล์ .env ขึ้นมาแก้ไข
nano .env

ตัวแปรสำคัญในไฟล์ .env ที่ต้องกำหนดค่าจริง:

ชื่อตัวแปร (Key) คำอธิบาย ตัวอย่างค่า
GOOGLE_API_KEY API Key ของ Gemini จาก Google AI Studio (จำเป็นสำหรับ Vision OCR & QA Reasoning) AIzaSy...
GEMINI_MODEL โมเดล Gemini ที่ต้องการใช้งาน gemini-2.5-flash
GMAIL_USER อีเมล Gmail สำหรับส่งรายงานผล QA อัตโนมัติ your_email@gmail.com
GMAIL_APP_PASSWORD App Password 16 ตัวอักษร (สร้างจาก Google Account Security) xxxx yyyy zzzz wwww
SECRET_KEY คีย์สำหรับเข้ารหัส Session ของ Flask Authentication สร้าง string สุ่มยาว 32+ ตัว
FRONTEND_PORT พอร์ตของ Web Frontend UI (เข้าใช้งานผ่าน Browser) 5173
BACKEND_PORT พอร์ตของ Backend API Service (Flask / Gunicorn) 8125
DB_PORT พอร์ตของ QA Agent Database (pgvector) 8123
AUTH_DB_PORT พอร์ตของ User Authentication & Audit Database 8124

Build Image & เริ่มทำงาน Container ด้วย Docker Compose

สร้าง Container ทั้งหมดและเริ่มทำงานในโหมด Background

สั่งให้ Docker Compose คอมไพล์ Frontend, ติดตั้ง Dependencies ของ Backend และเริ่มรัน Services ทั้งหมด:

bash 
# สั่ง Build และ Start Container ในโหมด Detached
docker compose up -d --build

ตรวจสอบสถานะของ Container ทั้งหมดว่าขึ้นเป็น Up (healthy) หรือไม่:

bash 
docker compose ps
✅
เมื่อคำสั่งเสร็จสิ้น จะมี Container ทำงานอยู่ 5 ตัว:
• qa_agent_db • spectra_auth_db • spectra_backend • spectra_frontend • spectra_mcp_server

สร้างโครงสร้าง Database เริ่มต้น (Bootstrap Script)

รันสคริปต์อัตโนมัติเพื่อเปิดใช้งาน Vector Extension, สร้างตารางทั้งหมด และบัญชีผู้ดูแลระบบ

รันคำสั่ง Bootstrap Database ภายใน Container Backend:

bash 
# เรียกสคริปต์สร้าง Database Schema และ Admin User
docker compose exec backend python scripts/init_production_db.py
🔑
ข้อมูลเข้าสู่ระบบเริ่มต้น (Default Admin Credentials):
• Username / Email: admin@domain.com
• Password: password123
(⚠️ แนะนำให้เปลี่ยนรหัสผ่านทันทีในหน้า Profile หลังเข้าใช้งานครั้งแรก)

ทดสอบการเข้าใช้งาน & ตรวจสอบ Log

เปิดเข้าใช้งานระบบผ่านเบราว์เซอร์และทดสอบความสมบูรณ์

1. เปิดเบราว์เซอร์แล้วเข้าใช้งานผ่าน URL:

http://<IP_SERVER_ของคุณ>:5173

2. ตรวจสอบ Endpoint สุขภาพของ Backend (Healthcheck API):

# ตรวจสอบตรงผ่าน Backend (Port 8125)
http://<IP_SERVER_ของคุณ>:8125/api/health

# หรือตรวจสอบผ่าน Web Frontend Proxy (Port 5173)
http://<IP_SERVER_ของคุณ>:5173/api/health

3. หากต้องการดู Live Log ของระบบเพื่อตรวจสอบความผิดพลาด:

bash 
# ดู Log ทั้งหมดแบบ Realtime
docker compose logs -f

# ดูเฉพาะ Log ของ Backend API
docker compose logs -f backend

# ดูเฉพาะ Log ของ MCP Server
docker compose logs -f mcp_server

กำหนดค่า Claude Desktop บนคอมพิวเตอร์ของคุณให้เชื่อมต่อกับ MCP Server บน Linux

json (claude_desktop_config.json)

      "args": [
        "d:/OCR-Github/OCR-Document/mcp-proxy/mcp-proxy.js",
        "http://<IP_SERVER_ของคุณ>:8000/sse"
      ]
    }
  }
}

คำสั่งที่เป็นประโยชน์ในการดูแลระบบ (Maintenance Commands)

คำสั่งสำหรับการอัปเดตโค้ด, การสำรองข้อมูล Database และการ Restart Service

bash (Maintenance Cheat Sheet) 
# ── 1. อัปเดตโค้ดใหม่จาก Git และ Rebuild ──
git pull origin main
docker compose up -d --build

# ── 2. สั่ง Restart ทุก Service ──
docker compose restart

# ── 3. ปิดระบบทั้งหมด (ข้อมูลยังคงอยู่บน Volume) ──
docker compose down

# ── 4. สำรองข้อมูล Database (Backup pgvector & Auth) ──
docker compose exec qa_agent_db pg_dump -U qa_admin qa_agent_db > backup_qa_$(date +%Y%m%d).sql
docker compose exec spectra_auth_db pg_dump -U postgres postgres > backup_auth_$(date +%Y%m%d).sql

# ── 5. ล้าง Cache ขยะของ Docker ที่ไม่ได้ใช้งาน ──
docker system prune -f
