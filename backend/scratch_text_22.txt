|  | Draft LPI | สถานะเริ่มต้นของ LPI ก่อนส่งข้อมูลไปยังหน่วยงาน ยังแก้ไขข้อมูลได้อย่างอิสระ |
|  | HS Code | Harmonized System Code — รหัสพิกัดศุลกากรสากลที่ใช้จำแนกประเภทสินค้า เป็นตัวกำหนดว่าสินค้ารายการใดต้องขอใบอนุญาตจากหน่วยงานใด |
|  | Permission_Goods | ตารางข้อมูลหลัก (Master Data) ที่ใช้ตรวจสอบว่า HS Code ใดต้องขอใบอนุญาตจากหน่วยงานใดบ้าง |
|  | Authority / หน่วยงาน | หน่วยงานราชการที่มีอำนาจออกใบอนุญาตสินค้าควบคุม เช่น อย. (สำนักงานคณะกรรมการอาหารและยา) ซึ่งเป็นหน่วยงานเดียวที่ระบบรองรับใน Phase นี้ |
|  | NSW | National Single Window — ระบบเชื่อมโยงข้อมูลอิเล็กทรอนิกส์ ณ จุดเดียวของภาครัฐ ใช้รับ-ส่งคำขอใบอนุญาตกับหน่วยงานราชการ |
|  | NSW ID | รหัสประจำตัว 29 หลักที่ลงทะเบียนไว้กับระบบ NSW สำหรับระบุตัวตนผู้ยื่นคำขอ/ผู้รับมอบอำนาจ |
|  | Ezybus | ระบบตัวกลาง (Middleware) รับ-ส่งข้อมูลคำขอใบอนุญาตและเอกสารตอบกลับระหว่างระบบ EzySuite กับหน่วยงานราชการผ่าน NSW |
|  | EzySuite | ระบบหลักฝั่งผู้ใช้งาน TIFFA ที่เชื่อมต่อรับข้อมูลตอบกลับจาก Ezybus และให้บริการ Open API แก่ผู้ใช้ภายนอก |
|  | MGT (หน้า MGT) | หน้าจอจัดการข้อมูลคำขอใบอนุญาตแบบละเอียด แบ่งเป็น Tab ส่วนควบคุม, ส่วนรายการ และสรุป สำหรับกรอก/ตรวจสอบข้อมูลก่อนส่งคำขอ |
|  | TIFFA | Thai International Freight Forwarders Association — ผู้พัฒนาและดูแลระบบ 69A-TIFFA-RGP รวมถึงเป็นผู้ดูแล Master Data บางส่วน เช่น Master Permission Goods |
|  | Production Profile | ข้อมูล Profile ที่ลงทะเบียนไว้กับระบบ NSW สำหรับยืนยันสิทธิ์การยื่นขอใบอนุญาตในนามบริษัท/หน่วยงานนั้นๆ |
|  | ผู้รับมอบอำนาจ | บุคคลที่บริษัทผู้นำเข้ามอบหมายให้ดำเนินการยื่นขอใบอนุญาตแทน ต้องมีเลขบัตรประชาชน 13 หลักและข้อมูลลงทะเบียนกับ NSW |
|  | Declaration / ใบขน | เอกสารใบขนสินค้าขาเข้า-ขาออกที่ต้องผ่านการตรวจสอบว่าสินค้าที่บรรจุอยู่มีใบอนุญาตครบถ้วนก่อนส่งไปยังกรมศุลกากร |
|  | Client Information Center | หน้าจอจัดการข้อมูลบริษัทลูกค้า (Client) รวมถึงข้อมูลผู้รับมอบอำนาจของแต่ละบริษัท |
|  | Status: Draft (สีเทา) | LPI ที่เพิ่งถูกสร้างขึ้น ยังไม่เคยส่งข้อมูลไปยังหน่วยงาน |
|  | Status: Draft (สีแดง) | LPI ที่เคยส่งแล้วได้รับสถานะ Error และผู้ใช้แก้ไขข้อมูลแล้วแต่ยังไม่ได้ส่งซ้ำ |
|  | Status: Sent | LPI ที่ส่งข้อมูลไปยังหน่วยงานแล้ว อยู่ระหว่างรอผลการพิจารณา |
|  | Status: Error | LPI ที่หน่วยงานตอบกลับว่าข้อมูลผิดพลาดหรือถูกปฏิเสธ |
|  | Status: Completed | LPI ที่หน่วยงานอนุมัติแล้วและออกเลขที่ใบอนุญาตให้เรียบร้อย |
|  | Status: Cancel | LPI ที่ถูกยกเลิกคำขอหลังได้รับการอนุมัติแล้ว (ทำได้เฉพาะสถานะ Completed เท่านั้น) |
|  | SEC1.2 (Req No. Placeholder) | รหัสอ้างอิงที่ใช้แทน REQ ID สำหรับ Test Case ในหัวข้อ 1.2 EzySuite Open API เนื่องจาก SRS V5.0 ระบุไว้ว่า "ไม่พบข้อมูล" (Section นี้ยังไม่มีการกำหนด Functional Requirement เป็น REQ ID อย่างเป็นทางการ) จึงใช้เลขอ้างอิงตามหมายเลขหัวข้อในเอกสาร SRS (Section 1.2) แทน เพื่อคงไว้ซึ่ง Traceability |
|  | BVA | Boundary Value Analysis — เทคนิคออกแบบ Test Case โดยทดสอบค่าที่ขอบเขต (ต่ำสุด/สูงสุด/เกินขอบเขต) ของ Field ที่มีข้อจำกัด |
|  | Positive / Negative Case | Positive คือ Test Case ที่ทดสอบ Flow การทำงานปกติและคาดหวังผลสำเร็จ / Negative คือ Test Case ที่ทดสอบกรณีข้อมูลผิดพลาดหรือขอบเขตผิดปกติ คาดหวังให้ระบบจัดการข้อผิดพลาดได้ถูกต้อง |
